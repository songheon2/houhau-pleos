# 호우하우

호우하우는 안내 중인 자동차 경로를 실시간 강수량·호우특보, 침수 이력·지형 데이터와 대조해 침수 위험 구간을 찾아내고, 이를 피하도록 경로를 조정해 음성으로 안내하는 서비스입니다.

이 저장소는 호우하우의 **웹 프로토타입**입니다. 위험 분석과 경로 탐색 로직이 여기서 동작하며, Pleos Connect 기반 차량용 앱은 이 로직 위에 만들 계획입니다([차량용 앱 계획](#차량용-앱-계획-pleos-connect)). 시범 지역은 광주광역시입니다.

> **이 서비스는 실제 도로 통제와 침수 여부를 확인하지 않습니다.** 지하차도 통제, 재난문자, 경찰·지자체 안내를 먼저 따르세요.

## 해결하려는 문제

집중호우 때 지하차도와 저지대 도로는 짧은 시간에 물에 잠깁니다. 운전자는 재난문자를 받아도 안내된 위험 지역이 내 경로에 있는지 바로 판단하기 어렵고, 실제 침수와 도로 통제 사이에는 시간차가 있습니다. 일반 내비게이션은 교통 흐름과 통제 정보로 경로를 고르기 때문에, 강수량 변화와 과거 침수 이력, 지형을 함께 본 선제적 회피에는 한계가 있습니다.

호우하우는 도로가 통제된 뒤가 아니라 위험이 예상되는 단계에서 미리 회피 경로를 제시합니다.

## 주요 기능

- **강수 단계별 회피 경로:** 시간당 강수량과 호우 특보에 따라 피할 구역을 늘립니다.
- **회피 근거 표시:** 피한 구역, 아직 지나는 구역, 가장 빠른 길 대비 늘어난 시간과 거리를 보여줍니다.
- **기상청 연동:** AWS 관측소의 분 단위 강수량(없으면 초단기실황)과 호우 특보를 반영합니다. 날씨는 현재 위치나 광주·전남에서 고른 지역 기준으로 보여주고, 경로는 출발지, 운행 중에는 차 위치의 날씨로 판단합니다.
- **장소 검색:** 카카오 로컬 API로 광주 안의 장소를 찾습니다.
- **운행 화면:** 3D 지도, 회전 안내, 도착 예정 시각, 위험 구역 경고를 보여줍니다. 지금은 **시연 주행**이며 실제 GPS를 쓰지 않습니다.
- **운행 중 경로 변경 요청:** 비가 강해지면 남은 길을 다시 판단합니다. 더 나은 경로가 있으면 지도에 두 경로를 함께 보여주고, 이유를 카드에 설명하며 요약을 음성으로 읽은 뒤 운전자가 고르게 합니다.
- **템플릿 기반 설명:** 경로 선택과 경로 변경 이유는 서버가 계산한 수치(강수량, 강수 단계, 위험 구간 수, 추가 소요시간)를 정해 둔 문장 틀에 채워 만듭니다. 생성형 AI를 쓰지 않으므로 계산 결과에 없는 내용이나 안전을 보장하는 표현이 나오지 않습니다.
- **날씨 배경:** 강수량과 시간대에 따라 하늘, 구름, 비, 번개가 바뀝니다. 경로 계산과는 무관한 장식입니다.

키가 없어도 시연할 수 있습니다. 기상청 키가 없으면 강수량을 직접 고르고, 카카오 키가 없으면 데모 지점 목록을 씁니다.

### 강수 단계

| 시간당 강수량 | 단계 | 반드시 피함 | 되도록 피함 |
| --- | --- | --- | --- |
| 30mm 미만 | 0 | 없음 | 없음 |
| 30mm 이상 | 1 | 지하차도 | 침수 이력(우선 회피) |
| 50mm 이상 | 2 | 지하차도, 침수 이력(우선 회피) | 침수 이력(일반, 주변보다 높은 편) |
| 70mm 이상 | 3 | 지하차도, 침수 이력 전체 | 없음 |

'되도록 피함' 구역은 우회 시간이 벌점보다 작을 때만 돌아갑니다. 호우주의보는 최소 1단계, 호우경보는 최소 2단계로 올립니다. 기준값은 [strategies.yaml](backend/app/config/strategies.yaml)에서 바꿉니다.

### 경로 알고리즘

화면은 `tiered_rain`만 씁니다. 나머지는 API의 `strategy` 값으로 비교할 때 씁니다.

| 이름 | 방식 |
| --- | --- |
| `tiered_rain` | 강수 단계에 따라 피할 구역을 늘립니다. 기본값입니다. |
| `hard_exclude` | 강수량과 관계없이 모든 위험 구역을 피합니다. |
| `rerank` | 후보 경로 중 소요시간과 위험 노출 점수의 합이 가장 작은 경로를 고릅니다. |
| `baseline` | 회피 없이 후보 중 가장 빠른 길입니다. 비교 기준입니다. |

네 알고리즘 모두 같은 후보 묶음에서 고르므로, 강수 단계가 올라도 소요시간이 줄어드는 일이 없습니다. 새 알고리즘은 [strategies/](backend/app/strategies/)에 파일을 추가하고 `@register`를 붙이면 API에서 쓸 수 있습니다.

## 구조

```
브라우저 (React + MapLibre)
   │  /api/ (좌표와 검색어는 POST 본문으로만 전송)
   ▼
FastAPI
   ├─ 경로 알고리즘 ─ Valhalla (서버 프로세스 안에서 실행, OSM 광주 타일)
   ├─ 위험 구역 레이어 (risk_zones.geojson)
   ├─ 설명 문장 템플릿 (route_explainer.py)
   ├─ 기상청 API허브 또는 공공데이터포털
   └─ 카카오 로컬 API
```

좌표, 검색어, 경로는 DB나 로그에 저장하지 않습니다. 카카오에는 검색어와 검색 범위만, 기상청에는 좌표가 아닌 5km 격자 번호만 보냅니다. 지도 타일은 브라우저가 OpenFreeMap에서 받습니다.

| 경로 | 설명 |
| --- | --- |
| `POST /api/route` | 경로 계산과 회피 근거 |
| `POST /api/route/guidance` | 선택한 경로의 회전 안내 |
| `POST /api/route/explain` | 경로 선택 이유 문장 (템플릿) |
| `POST /api/route/reroute` | 운행 중 비가 강해졌을 때 남은 경로 재판단과 변경 이유 문장 |
| `POST /api/search` | 장소 검색 |
| `POST /api/tts` | 안내 음성 합성 (Supertonic 서버, 없으면 브라우저 음성) |
| `POST /api/weather` | 지정한 위치의 강수량과 특보 (광주·전남) |
| `GET /api/weather` | 광주광역시 기준 강수량과 특보 |
| `GET /api/weather/regions` | 날씨 지역 목록 |
| `GET /api/risk-zones` | 위험 구역 지도 레이어 |
| `GET /api/strategies` | 알고리즘 목록 |
| `GET /api/app-config` | 화면 설정 |
| `GET /api/demo-points` | 데모 지점 |

## 테스트 환경과 필요한 설정

| 항목 | 개발·시험에 쓴 환경 |
| --- | --- |
| OS | Windows 11 |
| 브라우저 | Microsoft Edge (Chromium 계열) |
| Python | 3.12 (conda 환경 `disaster-action-guide`) |
| Node.js | 24.13 |
| 경로 엔진 | Valhalla 3.9.1 (pyvalhalla, 백엔드 프로세스 안에서 실행) |
| 도로 데이터 | OpenStreetMap 한국 추출본(Geofabrik)을 광주 범위로 잘라 만든 타일 |

필요한 설정은 다음과 같습니다.

- **경로 엔진 타일 (필수):** 처음 한 번 만들어야 합니다([실행 방법](#실행-방법) 2단계). 타일이 없으면 경로 계산이 되지 않습니다.
- **API 키 (선택):** 카카오·기상청 키를 `.env`에 넣으면 실제 장소 검색과 실시간 강수량을 씁니다. 없으면 데모 지점과 직접 고른 강수량으로 시연합니다(3단계).
- **음성 (선택):** `HOUHAU_TTS_URL`이 비어 있으면 브라우저 음성으로 읽습니다.
- **위치 권한 (선택):** 현재 위치의 날씨는 브라우저가 위치를 허용하고 localhost나 HTTPS로 접속했을 때만 씁니다.

## 실행 방법

Windows 기준입니다. Python 3.12(conda), Node.js 24가 필요합니다. 명령은 프로젝트 루트에서 실행합니다.

### 1. 설치

```powershell
# 백엔드
conda create -n disaster-action-guide python=3.12 -y
conda run -n disaster-action-guide python -m pip install --require-hashes -r backend/requirements.local.lock
conda run -n disaster-action-guide python -m pip install -r backend/requirements.team.txt

# 프론트엔드
cd frontend; npm ci; cd ..
```

### 2. 경로 엔진 타일 만들기

한국 OSM 데이터(약 290MB)를 받아 광주 범위로 잘라 `.local-data/valhalla/`에 만듭니다. 처음 한 번만 하면 됩니다.

```powershell
conda create -n disaster-action-guide-osm -c conda-forge --override-channels osmium-tool=1.19.1 -y
.\data_pipeline\build_valhalla_tiles.ps1
```

`VALHALLA_TILES_OK`가 출력되면 성공입니다.

### 3. API 키 넣기 (선택)

```powershell
Copy-Item .env.example .env
```

`.env`를 열어 키를 넣습니다. 로컬 실행은 이 파일을 읽고, 서버는 `backend/.env`를 읽습니다(항목은 `backend/.env.example`). **두 파일 모두 Git에서 제외됩니다.** 키를 저장소나 프론트엔드 코드에 넣지 마세요.

| 변수 | 발급처 | 필요한 활용 신청 |
| --- | --- | --- |
| `KAKAO_REST_API_KEY` | Kakao Developers | 로컬 API |
| `KMA_SERVICE_KEY` | 기상청 API허브 또는 공공데이터포털 | 초단기실황, 호우 특보 |
| `KMA_AWS_KEY` (선택) | 기상청 API허브 | AWS 매분자료, 지점정보 |
| `HOUHAU_TTS_URL` (선택) | 직접 띄운 Supertonic 서버 | 비우면 브라우저 음성 |

기상청 키 종류는 자동으로 구분합니다. API허브에서는 특보 현황(`wrn_now_data.php`)을 신청해야 합니다.

### 4. 서버 켜기

PowerShell 창 두 개에서 각각 실행합니다.

```powershell
.\scripts\dev-backend-conda.ps1
```

```powershell
.\scripts\dev-frontend.ps1
```

http://127.0.0.1:5173 으로 접속합니다.

### 5. 시연하기

1. 날씨 카드에서 `데모 모드`를 켜고, `데모 지점에서 고르기`로 출발지 광주송정역과 목적지 광주역을 정한 뒤 `경로 찾기`를 누릅니다.
2. `0mm` → `35mm` → `55mm` → `75mm`를 차례로 눌러 경로와 지나는 구역이 바뀌는 것을 봅니다. 이 구간의 `0mm`와 `35mm`는 같은 경로입니다.
3. `0mm`로 돌아간 뒤 `안내 시작`을 눌러 운행 화면을 봅니다. 오른쪽 위에서 배속을 바꿀 수 있습니다.
4. 출발 직후 오른쪽 위 `시연 강수`에서 `75`를 누릅니다. 알림과 음성이 나오고 변경 요청 카드가 뜹니다. 같은 구간에서 `35`는 남은 길에 피할 구간이 없어 알림만 나오고, 전체 경로의 30~40% 지점에서는 `75`도 더 나은 경로가 없다는 경고만 나옵니다.
5. `경로 변경`을 누르면 지도를 유지한 채 새 경로로 안내하고, `현재 경로 유지`를 누르면 남은 위험 구간을 알려준 뒤 계속 달립니다.

### 테스트

```powershell
cd backend; conda run -n disaster-action-guide python -m pytest tests -q; cd ..
cd frontend; npm run build; npm run lint; cd ..
```

백엔드 테스트는 실제 엔진, 카카오, 기상청 없이 돌아갑니다.

## 차량용 앱 계획 (Pleos Connect)

아래는 **계획이며 이 저장소에는 아직 구현되어 있지 않습니다.** 이 저장소의 경로 분석 서버를 그대로 쓰고, Kotlin 기반 Android Automotive 앱을 Pleos Connect Emulator에서 검증할 계획입니다.

| SDK | 쓰임 |
| --- | --- |
| NaviHelper | 목적지와 현재 위치를 조회하고, 회피 경로를 경유지로 바꿔 `requestRouteWithWaypoints`로 기본 내비게이션에 반영. 별도 신청 없이 사용 가능 |
| Vehicle State (Wiper) | 와이퍼 고속 작동이 일정 시간 이어지면 위험 단계를 한 단계 올려 경로를 다시 판단. 와이퍼가 멈췄다고 단계를 낮추지는 않음 |
| FusedLocation | 공개 전(Coming Soon)이라 NaviHelper 위치 정보로 대신하고, 공개되면 전환 |
| TextToSpeech | 공개 전이라 서버 `/api/tts`가 만든 음성을 앱에서 재생하고, 공개되면 전환 |
| SpeechToText | 공개되면 음성으로 목적지 설정과 주요 기능 조작에 적용 |

기본 내비게이션의 경로 좌표를 받을 수 없으면, 서버가 같은 출발지·목적지로 경로를 따로 계산해 위험을 판단합니다. 경유지 사이 구간은 기본 내비게이션이 다시 계산하므로 모든 구역을 반드시 피한다고 보장할 수는 없습니다.

## 현재 한계

- 하천변은 자료가 없어 위험 구역에서 뺐습니다. 서버의 회피 규칙은 남아 있어, 자료를 넣으면 화면에 다시 나타납니다.
- 지하차도 목록의 출처를 확인하는 중입니다. 운암지하차도는 OpenStreetMap에 터널 표시가 없어 빠져 있습니다.
- 동구·남구의 일부 지번은 본번만 확인되어 위치 오차가 큰 28개 구역을 비활성 상태로 보관합니다.
- 강수량은 가까운 AWS 관측소의 최근 60분 누적값입니다. 약 3분 늦고, 관측소 값이라 내 위치의 값은 아닙니다. `KMA_AWS_KEY`가 없으면 1시간 단위 관측값을 씁니다.
- 날씨 위치는 5km 격자 단위입니다. 특보는 가장 가까운 시군 기준이라 경계 근처에서는 이웃 시군 특보를 볼 수 있고, 세분된 시군은 일부 구역의 특보도 시군 전체 특보로 표시합니다.
- 경로와 위험 구역은 광주 안에서만 됩니다. 전남은 날씨 확인만 됩니다.
- 현재 위치는 브라우저가 허용한 경우에만 쓰며, HTTPS 또는 localhost에서만 동작합니다. 기본 화면은 GPS를 먼저 요청하지만, GPS가 없는 PC는 Wi-Fi나 IP 위치라 오차가 클 수 있습니다. 운행 화면은 GPS를 쓰지 않습니다.
- 운행 화면은 시연 주행입니다. 실제 위치 추적, 경로 이탈 재탐색, 회전 음성·차선·카메라 안내가 없습니다. 음성은 경로 변경 알림과 요약만 읽습니다.
- 변경 요청을 기다리는 동안 시연 주행이 멈춥니다. 실제 주행에 붙이려면 응답 없는 운전자 처리를 따로 정해야 합니다.
- 와이퍼 감지와 Pleos 기본 내비게이션 연동은 아직 없습니다([차량용 앱 계획](#차량용-앱-계획-pleos-connect)).
- 위험 구역을 모두 피하는 경로를 찾지 못하면 가장 적게 지나는 경로를 경고와 함께 보여줍니다. 구역에 둘러싸인 곳이나 구역 안에서는 전부 피할 수 없습니다.
- 실시간 교통을 반영하지 않습니다.
- 새 지점의 날씨 조회는 서버 전체에서 분당 60회, 하루 5,000회로 제한합니다. 사용자별 제한은 아닙니다.
